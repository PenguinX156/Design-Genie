# UI builder

Read the product brief, `design scan`, and `.design/` before editing. Map user tasks, hierarchy, content, layout, responsive behavior, and interaction states. Use the app's framework and shared components where sensible. Choose resources for a stated need and check each asset's license; a catalog link is not permission to copy.

Build the core task flow first. Concentrate extra visual engineering in the recorded signature moments. Include loading, empty, error, hover, focus, keyboard, and reduced-motion states as applicable. Run the application and capture desktop, tablet, and mobile with `design capture`; inspect actual renders and interactions. Use `visual-critic` to prioritize fixes, iterate up to three rounds by default, and run `design audit`. Do not describe a significant interface as polished without inspecting it in a browser.
